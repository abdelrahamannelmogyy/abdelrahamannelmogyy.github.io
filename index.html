It operated at 85,000+ outbound calls a day for leading Gulf telecom operators. The value was not only the calling. It was the connected system: conversational AI, API integration, event-driven automation, data engineering, SQL Server, analytics and performance monitoring working together.

  3. AutomatedCall events and outcomes are captured through APIs and webhooks and logged automatically, and the agent hands over to a human when the customer asks for a person.
  4. IntegratedReal-time lookup APIs connect the agent to SQL Server account data. APIs and webhooks connect the calling solution to a data-processing flow and, through it, to SQL Server.
  5. MeasuredObserved answer rates of about 30% overall, over 70% on customers who promised to pay and under 10% on bad-debt segments, at 85,000+ outbound calls a day.

12Challenges, engineering decisions and trade-offs
Challenges
Response speed

In a voice call every pause is noticeable and every data lookup adds delay. Response speed was the hardest part of the project.

Wrong or missing data

When the agent read the data wrongly, the case was handled with a human call and a message.

Staying within bounds

The agent had to stay within the defined customer-behaviour statuses.

Engineering decisions
  • Fetch account data during the call, when it is needed.
  • Keep the agent within defined customer-behaviour statuses.
  • Capture call events and log outcomes automatically instead of by hand.
  • Roll out in small batches first, with test calls by staff, review of call recordings, outcome dashboards and comparison with human agents.
  • Hand over to a human agent when the customer asks for a person.
Trade-offs
  • Live lookups keep the conversation accurate but add delay, so data is fetched only when it is needed.

14Lessons learned and future improvements
Lessons learned
  • Response speed is a product feature in a voice agent, not only a technical detail.
  • A defined set of statuses keeps every call predictable and measurable.
  • Capturing events automatically turns every call into data that can be analysed.
Future improvements
  • Make every part of the system run locally, including the LLM, so the solution becomes a fully local application.
